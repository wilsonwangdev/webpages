从零用 Tauri 构建 AI Agent 桌面端

2026-07-29 · 系列连载中 · #Tauri #工程实践

这是一个实验性项目的开篇——用 Tauri v2 构建一个对标 Codex CLI 和 Hermes Desktop 的 AI Agent 桌面客户端，取名 Ara Desktop。这篇文章记录最初的选型决策和项目骨架搭建过程。

为什么不是 Electron？

Hermes Desktop 用的是 Electron，打包后 .app 大小 310 MB。Ara 用 Tauri，同样功能的骨架打出来 11 MB。差距来自 Electron 内置了完整的 Chromium 渲染引擎，而 Tauri 使用系统的 WebView。

但包体大小不是唯一的决策因素。更重要的是：

  • Rust 编译器的错误信息对 agent 友好。 在 agent 开发模式下，Rust 精确的编译错误比 JS 的运行时 undefined 错误更容易自动修复。
  • 安全性。 Tauri 的权限模型比 Electron 严格，每个 API 调用需要显式声明。对于运行第三方代码的 Agent 客户端，这点很重要。
  • 代价是生态成熟度。 Electron 社区问了十年问题，Tauri v2 才刚稳定。遇到冷门 bug 可能需要自己排。

最终决策是一个权衡：Ara 的目标是探索 Tauri 在复杂桌面应用的工程实践，所以接受生态不成熟的风险。

开发环境搭建

Mac mini (M系列) 上搭建 Tauri v2 开发环境只需要三步：

# 1. 安装 Rust
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# 2. 安装系统依赖（macOS 需要 Xcode CLI tools）
xcode-select --install

# 3. 安装 Tauri CLI
npm install -g @tauri-apps/cli

前端用 React + TypeScript + Vite 8，包管理器从 npm 切换到 pnpm（避免幽灵依赖和节省磁盘空间）。

Tauri 的 build 流程很简单：Vite 构建前端 → tauri-build 编译 Rust → electron-builder 等价物打包成 .app。第一次编译要下载 400+ crates，约 5 分钟。后续增量编译秒级。

第一个坑：配置文件兼容性

在 tauri.conf.json 中写 app.title 字段会导致编译失败——tauri-build v2.6.3 不认识这个字段。原因是 Tauri v2 的 Rust crate 版本和 CLI 版本需要严格对齐，而配置文件 schema 在两个版本之间有细微差异。

解决方案：移除 app.title，在 app.windows[0].title 中设置窗口标题。

包体对比

                    .app 大小    安装包 (.dmg)
Electron (Hermes)    310 MB       ~150 MB
Tauri (Ara)           11 MB        3.6 MB

Tauri 的 .app 只有 Electron 的 1/28。这是最大的差异化优势。
